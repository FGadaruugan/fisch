# SS 2 — Settings System ба нөөц удирдлага

Огноо: 2026-10-16. Төлөв: хэрэглэгч 2026-10-16-нд баталсан; шууд хэрэгжүүлэхийг хүссэн.
Суурь: d541791c4c0d28e3e0163644137d156dab94a859.

## Зорилго ба нэр

SS = Settings System, FSFS = Fisch System. Одоогийн JavaScript + CSS тоглоомын
Settings-ийг ангилал, хайлт, ойлгомжтой тайлбартай, утсанд эвтэйхэн шинэчилнэ.
ColorOS 2-ын Lagoon өнгө төрхийг үргэлжлүүлж, хэрэглэгчийн үзүүлсэн нөөц удирдах
дэлгэцийн багц/хэмжээ/явцын санааг Fisch-ийн бодит файлд тохируулна.
Таталт нь тоглоомын static файл; загас, мөнгө, XP-ийн export биш.

Энэ ажил хоёр шалгаж болох үе шаттай: A — SS 2 интерфэйс ба тохиргоо,
B — бодит нөөц таталт ба офлайн static файлын ажиллагаа. Хоёул дуусаж байж энэ
загварт тайлбарласан SS 2 бүрэн гарсан гэж мэдээлнэ.

## Одоогийн кодоос баталсан байдал

- js/ui/settings.js одоо бүх тохиргоог нэг урт жагсаалтаар зурдаг.
- js/performance.js тохиргоог normalize хийдэг; үндсэн key fisch3d.settings.v1.
- js/main.js settings command нь graphics, FPS pacer, дуу, local хадгалалтыг холбоно.
- js/ui.js нь live FPS, install, support хэсгийг тусад нь шинэчилдэг.
- Build одоогоор 22 файл, 1,253,361 raw byte орчим. Энэ нь зөвхөн аудитын тоо,
  эцсийн таталтын хэмжээ биш; шинэ build бүр дахин хэмжигдэнэ.
- Тусдаа том texture/audio багц одоогоор байхгүй; 3D дүрсүүд кодоор үүсдэг.
- Офлайн service worker одоогоор байхгүй. Үүнийг шинэ модуль болгон нэмнэ.
- Account, Friends, Top болон cloud хадгалалт live серверийн холболт шаарддаг.
- Ахицын хадгалалт, зүрх, тохиргоо тусдаа key-тэй; тэдгээрийг resource cache устгалд оруулахгүй.

## Сонгосон бүтэц

A үе одоогийн Settings UI, command boundary дээр ажиллана. B үе ижил Settings-ийн
Нөөц ангилалд шинэ download manager, build manifest, хязгаарлагдсан service worker холбоно.
Бүх тоглоомыг дахин бичихгүй. Нэг том settings файлд бүх logic хийхгүй.

## A. SS 2 интерфэйс

### Ангилал

1. Ерөнхий — одоогийн тохиргооны хураангуй, бэлэн горим, профайл, Undo.
2. График — чанар/FPS/scale/харах зай, сүүдэр, манан, particles, гэрэл ба цаг.
3. Дэлгэц — одоогийн GUI сонголтууд, хамгаалагдсан үндсэн controls-ийн тайлбар.
4. Дуу — volume.
5. Сүлжээ — онлайн/local, холболтын төлөв, дахин холбох, шалгах.
6. Нөөц — багц, хэмжээ, явц, pause/resume/retry, нэмэлт файлын устгал.
7. Апп ба төхөөрөмж — install, device support.
8. Мэдээлэл — тоглоомын хувилбар, SS 2/ColorOS 2/FSFS тайлбар, release notes.

Desktop дээр авсаархан хажуугийн ангилал, утсан дээр хэвтээ scroll-той ангиллын товч.
Хайлтын талбар бүх ангиллын нэр, label, тайлбараас шүүнэ. Үр дүнгүй үед тодорхой
мэдэгдэл болон хайлтаа цэвэрлэх товч гарна. Search/category сонголт нь тоглоомын
тохиргоо биш, UI-ийн түр төлөв. Хайлтын focus болон scroll нь live FPS шинэчлэлтээр
алга болохгүй. Бүх контролын нэг л instance байна; тоймд давхар slider үүсгэхгүй.

### CSS ба хөдөлгөөн

Lagoon хөх/оюу өнгө, цагаан карт, жигд 16–24 px radius, 44 px-ээс багагүй touch
hit area. Search, сонгосон ангилал, таталтын явц тод ялгарна. Шаардлагатай жижиг
бичгийн contrast дор хаяж 4.5:1. Focus харагддаг, icon нь aria-label-тай.
320 px утас, хэвтээ утас, 768×600 tablet, desktop хэмжээнд modal overflow хийхгүй.
Reduced-motion сонголтыг CSS-ийн одоогийн OS preference-ээр хүндэтгэнэ.
Input талбар сонгож хуулж болдог; бусад UI дээр урт даралтын selection хамгаалалт хадгалагдана.

### Бэлэн горим, профайл, буцаах

- Хэмнэлт: quality=low, targetFps=30, renderScale=0.8, viewDistance=800,
  shadows=false, particles=false.
- Тэнцвэртэй: quality=auto, targetFps=60, renderScale=1, viewDistance=1400,
  shadows=true, particles=true.
- Өндөр чанар: quality=high, targetFps=60, renderScale=1.2, viewDistance=1800,
  shadows=true, particles=true.
- Горимууд volume, GUI, цаг болон аккаунтыг өөрчлөхгүй. FPS-ийг баталгаатай өсгөнө гэж амлахгүй.
- Өөрийн 3 хүртэл профайл, нэр 1–18 тэмдэгт. Зөвхөн normalizeSettings-ийн зөвшөөрсөн
  утгуудыг fisch3d.settings.profiles.v1 key-д хадгална. Ахицын snapshot оруулахгүй.
- Нэг алхмын Undo, хамгийн сүүлчийн хэрэглэгчийн өөрчлөлтийн өмнөх snapshot.
  Slider-ийн нэг чирэлт нэг өөрчлөлт байна; frame бүрийг тусдаа Undo болгохгүй.
- Ангиллын reset зөвхөн тэр ангиллын key-г DEFAULT_SETTINGS рүү буцаана.
- Өөрчлөгдсөн утгыг тэмдэглэнэ. Одоогийн утга болон Undo state нь UI update-аар синхрон байна.
- Font-size болон user-controlled reduced-motion toggle нь дараагийн нэмэлт; энэ хувилбарт орохгүй.

### Сүлжээ, хувилбар, мэдээлэл

Одоогийн connect_online/switch_local/account_refresh үйлдлийг дахин ашиглана.
Browser/OS-ийн Wi-Fi, mobile data тохиргоог өөрчлөх товч үүсгэхгүй. navigator.onLine
нь зөвхөн холболтын дохио; сервер хүрч байгааг батлахгүй. Тусдаа шалгах товч static
manifest-ийг cache:no-store fetch хийж хариу болон хугацааг хэмжинэ; үүнийг game
server latency эсвэл серверийн цаг гэж нэрлэхгүй. Auth refresh нь existing identity
шалгалтаа хадгална. Offline үед cloud боломжуудыг боломжгүй гэж зөв харуулна.

Fisch release version 0.2.0; SS 2 ба ColorOS 2 тусдаа UI/system label байна.
Шинэчлэлийн мэдээлэлд зөвхөн бодитоор гарсан өөрчлөлтүүдийг огноотой харуулна.
Release metadata тусдаа module-д байна; package ба lock metadata-тай нийцнэ.

## B. Нөөц удирдах

### Бодит багц ба хэмжээ

Гурван tier нь resource бүлгүүдийн нийлбэр байна:
- Үндсэн: тоглоомын HTML, CSS, үндсэн runtime болон шаардлагатай shared chunks.
- Нэмэлт: үндсэн + lazy account/social static модулиуд. Энэ нь cloud тоглолтыг офлайн болгохгүй.
- Бүрэн: дээрх + бодит app icons, install metadata, credits зэрэг үлдсэн static файлууд.

Картын нэр нь бодит content-оо тайлбарлана; байхгүй HD texture, skin эсвэл audio
багц зарлахгүй. Optional бүлэг хамааралтай shared chunk-аа хамтад нь тооцно.
Tier-үүдийн давхардсан файлыг нэг удаа тооцож, татна. Screenshot-ийн MB-ийг хуулж тавихгүй.

Build нь файл бүрийн relative URL, raw byte length, SHA-256 болон immutable build ID
бүхий resources.json үүсгэнэ. CSS болон main.js зэрэг unversioned файлын HTML
холбоосыг fisch-build=<build ID> query-тэй гаргаж, HTML-д build metadata нэмнэ.
Build ID-г үүсгэхдээ өмнөх generated metadata/query-г арилгасан canonical HTML
болон compiled asset-уудыг hash хийнэ; дараа нь шинэ metadata/query-г оруулж
эцсийн файл hash-уудыг тооцно. Давтан build яг ижил artifact гаргах ёстой. UI дээр "Файлын хэмжээ" гэж үзүүлнэ; compression,
cache metadata болон төхөөрөмжийн бодит storage usage-тай ижил гэж нэрлэхгүй.
Өөрийн manifest болон service worker control файлыг hash-ийн өөрийгөө заах циклд оруулахгүй.

### Download manager

Төлөв: idle, downloading, paused, completed, error, unsupported.
Файл бүр амжилттай татагдаж, хэмжээ/hash батлагдсаны дараа л CacheStorage-д орно.
Response.ok, origin, redirect очсон URL, allowlist шалгана; HTML error-г JS файл мэт
хадгалахгүй. Request нь credentials:omit, cache:no-store; зөвхөн manifest-ийн same-origin
static URL. Auth/session/API response таталт болон cache-д орохгүй.

Бүх таталтад нэг дараалал; нэг дарсан команд давхар job үүсгэхгүй. Pause нь одоогийн
fetch-ийг AbortController-оор зогсооно; дууссан файлууд үлдэнэ. Resume нь баталгаатай
хадгалагдсан файлуудыг алгасна. Хагас файл range-resume хийхгүй; тэр файлыг эхнээс татна.
Tab дахин нээхэд ижил build-ийн cache entries-ээс progress сэргээнэ.
Ажиллаж буй HTML-ийн build metadata болон manifest build ID зөрвөл шинэчлэх
мэдэгдэл гаргаж, өөр build-ийн таталтыг эхлүүлэхгүй. Хуучин build-ийг
шинэ build-ийн completed гэж тооцохгүй. Error/quota үед тайлбар болон Retry гарна;
таталт дуусаагүй байхад completed тэмдэг үзүүлэхгүй.

Бүх core файлууд батлагдсаны дараа core-ready marker бичнэ. Дутуу cache нь
офлайн navigation-д ашиглагдахгүй. Бодит bytes/file progress, completed counts харуулна.
Storage estimate боломжтой бол ойролцоо зайг харуулна; боломжгүй бол зохиомол хэмжээ гаргахгүй.

### Service worker ба хувилбар

Worker scope нь тухайн тоглоомын base path, жишээ нь /fisch/. Worker өөрийн
fisch-resources-v1 гэсэн prefix-тэй cache-уудтай л ажиллана. Downloaded build бүр
тусдаа cache нэртэй; шинэ core бүрэн бэлэн болох хүртэл хуучин ready build үлдэнэ.

- Navigation: network-first, offline бол хамгийн сүүлийн completed core HTML fallback.
- Hash-тай JS болон fisch-build query-тэй static файл: яг URL таарах баталгаатай
  completed cache, дараа нь network. Өөр build-ийн URL-ийг орлуулж өгөхгүй.
- Query-гүй mutable CSS/JS request: network; хуучин build-ийн файлаар fallback хийхгүй.
  Offline HTML нь өөрийн build-ийн versioned URL-уудтай тул хуучин/шинэ файл холилдохгүй.
- resources.json, query-гүй app manifest, account callback болон OAuth/API: network; account callback offline fallback үүсгэхгүй.
- Үл мэдэгдэх origin, method, URL дээр request-ийг өөрчлөхгүй.
- Waiting worker-ийг ажиллаж буй тоглолтын дундуур хүчээр солихгүй.

Worker registration secure context болон browser-ийн боломжийг шалгана. CacheStorage,
worker эсвэл quota боломжгүй байвал Нөөц хэсэг тодорхой unavailable төлөвтэй;
одоогийн online/static тоглолтыг хаахгүй. Offline local тоглолт нь зөвхөн core
таталт бүрэн, worker идэвхтэй болсон үед боломжтойг UI хэлнэ.

GitHub Actions dist hosting болон branch-based root hosting хоёрыг дэмжинэ:
resources.json-ийг тус бүрийн HTML, js эсвэл web/js URL-тэй тусад нь үүсгэнэ.
Worker-ийн scope болон URL нь document.baseURI-аас тооцогдоно. Manifest entry нь
base path-оос гарч болохгүй. Build/deploy шалгалт хоёр manifest-ийн бүх URL, hash,
хэмжээ, dependency closure, HTML build metadata, зөвшөөрсөн version query-г шалгана. Root болон dist manifest тус тусын build ID-тай.

### Устгал ба ахиц хамгаалалт

Үндсэн нөөцийг ердийн устгах товчоор устгахгүй. Optional бүлгийг устгахын өмнө
ямар бүлэг устахыг харуулна; бусад багцад хэрэгтэй shared/core файлыг үлдээнэ.
Resources cache delete нь localStorage/IndexedDB game progress, settings, favorites,
Supabase session болон бусад app cache-д огт хүрэхгүй. Browser data-г хэрэглэгч өөрөө
бүхэлд нь устгах нь тусдаа үйлдэл. Нөөц удирдах UI "Бүх browser data устгах" санал гаргахгүй.

## Кодын хил

- js/settings/catalog.js: ангилал, label, description, preset, зөвшөөрсөн key.
- js/settings/controller.js: normalize, profile, Undo, category reset, persistence.
- js/ui/settings.js: SS 2 renderer ба search/category event; focus хадгална.
- css/settings2.css: SS 2 layout, mobile, progress, controls.
- js/release.js: version болон release notes.
- js/network.js: холболтын дохио болон explicit static endpoint check.
- js/resources/manager.js: manifest validation, download state, cache/progress.
- js/resources/worker.js: нарийн хүрээтэй fetch/cache handler.
- scripts/build-resources.mjs: root/dist manifest, dependency closure, SW artifact.
- js/main.js, js/ui.js: settings болон live status-ийн холбоос; game reward logic оруулахгүй.
- tests/: settings, UI state, resources, worker routing, build manifest тусдаа тест.

## Хүлээн авах шалгуур

1. Одоогийн бүх settings key шинэ UI-д хүрэх боломжтой; хадгалсан утгууд алдагдахгүй.
2. Search/category өөрчлөх нь тохиргоо хадгалах команд илгээхгүй, focus алдахгүй.
3. Preset/profile/reset/Undo нь зөвхөн зөвшөөрсөн settings key-г өөрчилнө.
4. Slider drag нэг Undo, input/keyboard үйлдэл зөв ажиллана.
5. Profile name validation, quota failure, corrupt profile нь game save-д хүрэхгүй.
6. Live FPS, support, install state update нь typing/navigation-г дахин зурж таслахгүй.
7. Offline network hint болон бодит connectivity check-ийг ялгаж харуулна.
8. Manifest бүх файл/bytes/hash build-тэй таарна; tier size нь unique файлын нийлбэр.
9. Pause/resume/reopen/retry/quota/hash mismatch үед completed төлөв худлаа гарахгүй.
10. Partial core cache офлайн entrypoint болохгүй; шинэ release-д хуучин manifest-ийг идэвхжүүлэхгүй.
11. SW нь /fisch/-ээс гаднах URL, API/OAuth response-г cache хийхгүй.
12. Optional delete нь active core/shared файл болон бүх ахиц/settings/session-ийг хадгална.
13. 320 px, landscape phone, 768×600, desktop; keyboard/focus/reduced-motion/contrast шалгана.
14. Одоогийн 153 тест болон шинэ subsystem тестүүд, build, check, generated artifact шалгалт амжилттай байна.
15. Боломжтой browser дээр resource download/reload/offline smoke; төхөөрөмжийн GPU
    эсвэл browser runtime хязгаар байвал шалгаагүй хэсгийг ил тод мэдээлнэ.

## Нийтлэх

Тусдаа feat/ss2 branch. A ба B-г тус бүр regression тесттэй хэрэгжүүлээд бүх branch
review хийнэ. Settings CSS шинэ URL-тай байх тул өмнөх game.css cache-аас хамаарахгүй.
Code + generated runtime + manifest + worker нэг build-ээр, нэг release-д нийцнэ.
Main-д нэгтгэсний дараа live HTML, CSS, manifest/hash, worker URL болон install scope-г шалгана.
