# Sailing and Swimming Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Physically walk, swim and drive a boat between mapped islands in one sea.

**Architecture:** Combine existing terrain models for global movement and lazily stream island visuals. Keep the existing service travel protocol as an arrival checkpoint and guard asynchronous arrival against scene/account changes.

**Tech Stack:** Existing JavaScript/Three.js, Node tests, esbuild and GitHub Pages; no new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-15-sailing-design.md`

## Global Constraints

- One bounded 4000-unit sea and the existing three island centers.
- Forward/reverse boat caps 24/8, walking 5.5, swimming 4 units/s.
- Board/exit range 8; physical arrival margin 24; existing Level locks.
- GitHub Pages/PWA only; preserve account/save contracts and generated web assets.

## Review Focus

- A shoreline/pier must allow safe boarding and exit, including building/locked-shore obstruction.
- A long or hidden frame must not move the vessel through the coast or beyond the sea.
- An old arrival response must not change a switched account or disposed scene.
- Opening a menu while sailing must freeze inertia as well as input.
- A map destination must never trigger a service checkpoint before physical arrival.
